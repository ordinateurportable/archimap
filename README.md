# archimap

Карта постов из телеграм-каналов об архитектуре («Архитектурные
излишества», «Болота и церкви», ozzed expeditions). Конвейер на Python
разбирает выгрузки Telegram и находит в текстах места — города, улицы,
здания; трудные посты разбирают языковые модели. Фронтенд на React +
MapLibre показывает посты списком и на карте, сервер на Express хранит
правки админа и посты посетителей.

- `tools/` — конвейер разбора (Python, pymorphy3);
- `web/` — сайт (Vite, React, MapLibre GL);
- `server/` — сервер правок (Node, Express);
- `deploy/` — nginx, systemd и скрипты выкладки.

**Чего нет в репозитории.** Выгрузок каналов и фотографий — это тексты и
снимки авторов каналов; справочников (GeoNames, реестры наследия, OSM) —
они весят сотни мегабайт и скачиваются отдельно; разобранных постов, кэшей
геокодеров и ключей API. Что где взять — `data/README.md`. Ключи кладутся
в `tools/.geocoder-key`, `tools/.groq-key` и т. п., настройки сервера — в
`server/.env` по образцу `server/.env.example`.

Ниже — история и устройство разбора. Посты разложены на три группы по
тому, какая география в них упомянута.

## Как добавить ещё канал

Все каналы перечислены в `tools/sources.py` — скрипты и фронтенд берут
список оттуда. Чтобы подключить новый, достаточно положить рядом папку с
выгрузкой Telegram, дописать запись и перегнать данные:

```python
{"key": "swamps", "dir": "Swaps_and_churches",
 "channel": "swampsnchurches", "title": "Болота и церкви"}
```

Номера сообщений в разных каналах совпадают, поэтому у поста есть ещё и
поле `src`: вместе с `id` оно даёт уникальный ключ, из него же собираются
адрес фотографии `/photos/<канал>/<файл>` и ссылка на пост. Папки с
фотографиями продублированы в `web/vite.config.js` — конфиг не читает
Python, так что при добавлении канала правятся два места.

## Как запустить

```bash
cd server && npm install    # бэкенд правок
cd ../web && npm install    # фронтенд
npm run dev                 # поднимет и Vite, и сервер правок
```

`npm run dev` запускает два процесса сразу: Vite на 5173 и сервер правок
на 5174, который фронтенду виден как `/api` через прокси. По отдельности —
`npm run dev:web` и `npm run dev:api`.

Фотографии (58 тысяч файлов, 12.5 ГБ) не копируются в проект — дев-сервер
отдаёт их прямо из папок выгрузки, см. `web/vite.config.js`. Адрес имеет
вид `/photos/<ширина>/<канал>/<файл>`; если уменьшенной версии нет,
дев-сервер отдаёт исходник, так что нарезать фотографии для работы
необязательно.

## Как устроен разбор

Скрипты в `tools/` запускаются по порядку:

```bash
python tools/extract_posts.py     # выгрузка -> data/posts.json
python tools/build_gazetteer.py   # справочник топонимов -> data/gazetteer.json
python tools/build_districts.py   # районы и метро из OSM -> data/districts.json
python tools/classify.py          # три группы -> data/posts_classified.json
python tools/geocode_streets.py   # координаты улиц и объектов (сеть, кэш)
python tools/classify.py          # ещё раз — с точками из кэша
python tools/build_web_data.py    # компактные файлы -> web/public/data/
```

**extract_posts.py.** Телеграм выгружает альбом как несколько сообщений с
одинаковой датой, и подпись есть только у одного. Скрипт склеивает их и
проходит по всем каналам из `sources.py`: 61 835 сообщений превращаются
в 28 541 пост.

**build_gazetteer.py.** Русские названия берутся из GeoNames строго по
тегу языка `ru`. В самом `cities*.txt` все варианты свалены в одну колонку
без указания языка, и оттуда приезжают чеченское «Бетъырбух» вместо
Петербурга и монгольское «Бээжин» вместо Пекина. Российские города
дополняются официальным списком, регионы — субъектами РФ с привязкой к
крупнейшему городу.

**classify.py.** Русский склоняет топонимы, поэтому и текст, и справочник
приводятся к начальной форме через `pymorphy3`, а сравнение идёт по
цепочкам лемм: «в Нижнем Новгороде» → `('нижний', 'новгород')`.

Чтобы обычные слова не считались городами, работает несколько фильтров:

- топоним должен быть написан с заглавной (исключение — прилагательные
  вроде «московский»);
- `pymorphy` взвешивает разборы: у «Твери» весь вес на пометке `Geox`, у
  «Дома» и «Пушкина» его перетягивают обычное слово и фамилия. Спорные
  слова засчитываются только рядом с предлогом или словом «город»;
- стоп-лист строится по самому корпусу: если слово в текстах канала почти
  всегда пишется со строчной, как город оно не считается. Так отсеиваются
  настоящие городки из GeoNames с именами «Дом», «Так», «Мир»;
- «проспект Мира» — улица, а не туркменский городок Мир; «Тверской
  бульвар» — Москва, а не Тверь.

**Неизвестные слова.** Спорными считались слова, у которых морфология не
видит пометки `Geox`. Беда в том, что у слова, которого нет в словаре,
её не будет никогда — под это правило попадала почти вся зарубежная
география: подпись «Паттайя» без предлога рядом не засчитывалась. Теперь
неизвестное слово спорным не считается: обычным словом оно быть не может.

Расплата — фамилии и сокращения: «Теофиль Готье» цеплялся за городок
Готье в США, «БАМа» — за нигерийскую Баму. Поэтому сокращение (две
заглавные подряд) городом не считается, а мелкий зарубежный город
требует географического контекста рядом.

Отдельно ловятся исторические названия (Ленинград, Сталинград,
Кёнигсберг), разговорные сокращения («Питер», «в Нижнем») и
прилагательные — как списком для крупных городов, так и правилом
«Владикавказ → владикавказский».

**build_districts.py.** Города — не весь словарь канала: «в Беляеве» или
«на Таганке» в справочнике городов нет, и такие посты уходили в группу
«без географии». Районы, микрорайоны и станции метро тянутся из
OpenStreetMap через Overpass API (запросы лежат в `data/overpass_*.txt`).
Беляево при этом даже не официальный район Москвы, а станция метро и
историческая местность, поэтому метро тоже идёт в справочник.

Названия из одного слова фильтруются: среди 4 тысяч записей OSM попадаются
«Институт», «Российская» и «Спортивная». Частотный стоп-лист их не ловит —
в текстах канала они частые и со строчной, и с заглавной. Поэтому слово
остаётся, только если морфология знает его как топоним («Беляево», «Арбат»)
либо не знает вовсе, то есть это точно не обычное слово.

Районы добавляются последними и с маленьким весом: если название занято
городом, город важнее. Станция «Киевская» так и остаётся Киевом — по одной
лемме станцию и прилагательное «киевский» не разделить.

**Описания вместо топонимов.** «Рыбацкая деревня в Рязанской области»
цеплялась за петербургское Рыбацкое, «Художник на Садовом кольце» — за
село Садовое под Волгоградом. По лемме эти пары неразличимы, отличает их
грамматика: в описании прилагательное согласовано с существительным по
роду, числу и падежу («рыбацкая деревня», «садовое кольцо»), а название
города рядом с существительным не согласуется — «Коломенское — усадьба»,
средний род против женского. У городов-существительных такой формы нет
вовсе: «Москва, улица Пятницкая» — два существительных подряд, и
совпадение остаётся в силе.

Исключение — прилагательные-города («московский дворик»): для них такая
форма единственно возможная, поэтому у них проверяется только узкий
список слов вроде «бульвар» и «шоссе», иначе «Тверской бульвар» стал бы
Тверью.

Сами ориентиры, которых нет ни в GeoNames, ни в OSM (Садовое и Бульварное
кольцо, Хитровка, Зарядье), перечислены в `places_extra.py`.

**Сходство вместо места.** «У центра Твери совершенно петербургский
характер» ставил посту и Тверь, и Петербург, а «застройка напоминает
архангельские бараки Соломбалы» в посте про Рязань — Соломбалу. Теперь
слабыми считаются такие упоминания (функции `in_comparison` и
`drop_weak_mentions`):

- прилагательное от города («петербургский», «московский»);
- сравнение: «напоминает», «похож», «словно», «как в…» (но не «как в
  Москве, так и в Казани»), а вплотную — «в духе», «в стиле», «на манер».
  Оборот действует на семь слов и обрывается на конце предложения;
- прозвище: «назвал его „русским Марбургом“», «северная Венеция»;
- соперничество: «догнать и перегнать Москву»;
- название произведения или заведения в кавычках — только если перед
  кавычками стоит «фильм», «книга», «кафе», «гостиница» и т. п.: фильм
  «Инкогнито из Петербурга», кафе «Москва». Просто кавычки — это цитата
  или топоним («Воронежское море»), и место в них настоящее.

Сравнение, прозвище и название уступают любому месту, названному
всерьёз, а прилагательное — только месту своей вкладки: иначе
«московский ресторан „Прага“» уехал бы в Чехию, а «Питерский
двор-колодец» остался бы без Петербурга. Прилагательное при «области»,
«губернии», «уезде» — это регион, то есть настоящее место.

Ловушки морфологии:
- «с Новосибирском» pymorphy первым разбором читает как прилагательное
  «новосибирский» — слово с заглавной, среди разборов которого есть форма
  самого города, прилагательным не считается;
- «Касимов» приводится к имени «Касим», а «в Касимове» — к «касимов»,
  и город не находился ни в одной форме. Поэтому названия, которые
  морфология меняет, индексируются ещё и как написаны.

**Одноимённые ориентиры.** «Дворцовая площадь» из справочника ориентиров
петербургская, но такие площади есть и в Казани, и в Самаре. Ориентир или
район привязан к крупнейшему городу в радиусе 30 км (`city_of`; не к
ближайшему — GeoNames числит Лефортово отдельным «городом»). Если в посте
прямо назван другой город, а его — нет, ориентир отбрасывается
(`drop_foreign_landmarks`), и одноимённое место в названном городе ищет
геокодер. После слов «улица», «проспект», «метро» идёт название улицы или
станции, а не город: «улица Петербургская» в Казани — не Петербург.

**Местности.** «Посёлок Остров в Рязани» не находился: «остров» —
обычное слово, фильтры его отсеивают, а в OSM этого посёлка нет вовсе.
Теперь местности ловятся по слову-типу перед названием — посёлок, село,
деревня, хутор, станица, микрорайон, слобода (`find_localities`) — и
попадают в пост тегом рядом с улицами: «пос. Остров», «с. Бехово»,
«Ямская слобода». Название ставится в начальную форму («в хуторе
Крымском» → «х. Крымский»), если морфология знает слово; незнакомые
оставлены как в тексте, чтобы не выдумать «Большую Мурашкину». Во вкладку
«Россия» местность ведёт, только если в посте не названа другая страна.

После слова «село» или «посёлок» название засчитывается городом, только
если это основное имя места, а не вариант: у Мурманска в GeoNames записан
«Семёновский», и «село Семёновское» уезжало за Полярный круг.

**Улицы.** Улица сохраняется с типом и в начальной форме, как её пишут в
OSM: «в Шишмаревском переулке» → «Шишмаревский переулок», «на улице
Большой Дмитровке» → «улица Большая Дмитровка», «по 2-й Тверской-Ямской» →
«2-я Тверская-Ямская улица», а «улица Ленина» остаётся как есть
(`find_streets`, `normalize_street`).

## Точные точки

Город — слишком грубая точка: пост про Шишмаревский переулок стоял в
центре Петербурга. Теперь у поста бывают точные места, и на карте они
заменяют город, который уточняют (`mapPlaces` в `web/src/data.js`):

- **координаты в тексте** — «Координаты: 60.050942, 31.085751» у ozzed
  (`find_coordinates`). Подпись — текст перед координатами в той же строке
  или заголовок поста, вкладка — по ближайшему городу справочника;
- **улицы и объекты** — их ищет геокодер (см. ниже). Объекты — это
  названия в кавычках после «небоскрёб», «ДК», «гостиница», «ЖК» и т. п.
  («Лахта-центр») и сочетания вроде «Александровская колонна», «Казанский
  собор» (`find_objects`). Искать их надо в городе поста — его дают и
  прилагательные: в «петербургского небоскрёба „Лахта-центр“» Петербург
  назван только так (`context_cities`);
- **ориентиры и районы** из справочника — «Дворцовая площадь»,
  «Басманный район».

### Геокодер

`tools/geocode_streets.py` отправляет пары «город + улица» и «город +
объект» в Photon (photon.komoot.io, данные OpenStreetMap) и копит ответы
в `data/street_geocode.json`. Ответ принимается, только если название
совпало (без учёта «ё», дефисов и регистра) и точка лежит в названном
городе или рядом с ним: «улица Ленина» есть почти везде. Запросы идут по
одному, с паузой в секунду — сервис бесплатный. Первый прогон по корпусу
длится пару часов, повторные спрашивают только новое, а прерванный можно
просто запустить снова.

Геокодер берёт пары из разбора, а разбор — точки из кэша геокодера,
поэтому порядок такой:

```bash
python tools/classify.py          # находит улицы, объекты и города поста
python tools/geocode_streets.py   # координаты -> data/street_geocode.json
python tools/classify.py          # подставляет точки из кэша
python tools/build_web_data.py
```

### Wikidata и Викимапия

Объектов и местностей, которых нет в OpenStreetMap, много: заброшенные
лагеря, рабочие городки, народные названия. Для них после Geoapify
спрашиваются ещё два источника — с теми же проверками (название совпало,
точка в городе поста, одноимённых мест рядом нет):

- **Wikidata** (CC0, без ключа) — храмы, памятники, заметные здания,
  с вариантами названий: «Кулич и Пасха» находится по псевдониму;
- **Викимапия** (CC BY-SA) — неформальные места. Нужен ключ из
  wikimapia.org/api?action=my_keys в файле `tools/.wikimapia-key`
  (в git не попадает); без ключа шаг пропускается.

Точки из этих источников помечены в кэше полем `src`. Лицензия Викимапии
требует указывать источник и распространять производные данные на тех же
условиях, поэтому подпись стоит в подвале сайта.

```bash
# добрать то, чего не нашёл OSM, не тратя лимит Geoapify
python tools/geocode_streets.py --retry-missing --only wikidata
python tools/geocode_streets.py --retry-missing --only wikimapia
```

Короткие ссылки на Яндекс- и Google-карты (`yandex.ru/maps/-/…`,
`goo.gl/maps/…`, около 70 постов) без сети не расшифровать, они пока не
используются.

**Страны.** Название страны существительным теперь считается местом и
без предлога: у ozzed expeditions подпись к посту — просто «Камбоджа».
Прилагательные по-прежнему не считаются вовсе, иначе «Белорусский
вокзал» уехал бы в Минск.

Отдельная беда — родовые словосочетания. «Гостиный двор» и «Речной
вокзал» есть и в Москве, и в Костроме, и в Твери, но в OSM они записаны
как московская и петербургская станции метро. Такие названия — где
морфология знает каждое слово как обычное, без пометки `Geox` — теперь
засчитываются, только если в посте назван и сам город. Тверской речной
вокзал перестал уезжать в Москву.

**Страны.** Само по себе название страны — сигнал слабый: «Белорусский
вокзал» стоит в Москве, а «Китайский домик» — в Царском Селе. Поэтому
прилагательные не считаются вовсе, а существительное засчитывается только
в обороте «в <Стране>»: так добавилось 185 постов вроде «конная статуя в
Монголии». Россия по этому правилу не считается — города она не называет,
а «в России» встречается в каждом втором рассуждении канала.

## Оформление

Интерфейс сделан в духе iOS 8, в его тёмном варианте — каким он был в
Control Center, Podcasts и Videos: плоские цвета, волосяные линии,
размытые полупрозрачные панели и системная палитра 2014 года. Теней и
градиентов нет: глубина в iOS 7–8 передаётся слоями и прозрачностью,
а не объёмом.

Из типовых элементов системы: панель навигации с заголовком по центру,
сегментированные контролы вместо вкладок и переключателей,
сгруппированные таблицы с заголовками секций капсом, строки со шевроном
`›` и модальный экран с кнопкой «Готово» справа. Цвета — системные:
синий `#007AFF`, зелёный `#4CD964`, серый `#8E8E93`. На тёмном фоне
синий и фиолетовый осветлены, иначе не читаются.

Шрифт iOS 8 — Helvetica Neue, но просто назвать её в CSS нельзя. На
многих Windows-машинах стоит сторонняя «Helvetica Neue» со сломанной
кириллицей: браузер берёт именно её, и в русском тексте появляются
заглавные посреди слов («извозчичьих Санках»). Поэтому подключён Arimo —
он повторяет метрики Helvetica и Arial и содержит полную кириллицу. Без
сети всё откатывается на системный шрифт.

## Карта

Вкладка «Карта» работает на MapLibre GL (`web/src/components/MapView.jsx`).

Координаты у нас пока городские, поэтому на карту идёт не каждый пост
отдельной меткой, а одна точка на место с числом постов: 2172 точки по
России и 447 по остальному миру вместо 17 тысяч меток друг на друге.
Размер кружка пропорционален количеству постов, цвет — группе. Клик по
кружку открывает список постов этого места.

Когда появятся адреса домов, менять придётся только ключ группировки в
`buildGeoJSON` — остальное выдержит рост числа точек. Если точек станет
сильно больше, у geojson-источника MapLibre включается `cluster: true`.

Подложка — OpenFreeMap: полностью бесплатные векторные тайлы
OpenStreetMap, без ключа, регистрации и лимитов. Подложек три —
«Светлая» (`positron`, по умолчанию), «Подробная» (`liberty`, с домами и
метро) и «Тёмная» (`dark`); переключатель стоит в углу карты, выбор
запоминается в браузере. Список — в `web/src/mapStyle.js`.

Стиль скачивается и правится до передачи в MapLibre: OpenFreeMap
подписывает объекты как «Tverskaya ulitsa Тверская улица», а нам нужно
русское название (`name:ru`, если его нет — `name`). Заодно подписи
улиц включаются чуть раньше — с 11-го масштаба для крупных и с 13.5-го
для остальных. При смене подложки MapLibre выбрасывает наши слои, поэтому
они добавляются заново на каждый `style.load`.

У точки, к которой привязан ровно один пост, вместо кружка показывается
сама фотография. Превью рисуются на canvas и добавляются в стиль через
`map.addImage`, но только для того, что видно сейчас, и порциями по 30:
иначе на первой же отрисовке браузер полез бы за тысячей фотографий.

Точки фильтруются по вкладке: 870 постов упоминают и российский, и
зарубежный город, и без фильтра карта России разъезжалась на весь мир
из-за пары упоминаний Парижа.

Охват считается с поправкой на 180-й меридиан. Россия через него
переходит — Чукотка на +179, соседние точки на -179, — и обычный
`LngLatBounds` растягивался на весь глобус. Поэтому охват считается
дважды, как есть и со сдвигом западного полушария, и берётся тот, что уже.

### Воркер MapLibre и сборка

MapLibre 6 вычисляет адрес своего воркера в рантайме:

```js
new URL('maplibre-gl-worker.mjs', import.meta.url)
```

Бандлер такой путь не видит, файл рядом с бандлом не появляется, воркер не
стартует — и карта остаётся пустой **без единой ошибки в консоли**, потому
что падает загрузка модуля уже внутри воркера. Лечится в двух местах
`web/vite.config.js`:

- в деве — `optimizeDeps.exclude: ['maplibre-gl']`, чтобы Vite отдавал
  пакет как есть, вместе с соседними файлами;
- в сборке — плагин `maplibreWorker`, который кладёт
  `maplibre-gl-worker.mjs` и `maplibre-gl-shared.mjs` в `dist/assets/`,
  туда же, где лежит итоговый чанк.

### Проверка карты

Карту нельзя проверить, читая код: оба раза она ломалась молча. Поэтому
рядом лежит `web/check-map.mjs` — открывает приложение в настоящем Chrome,
проходит по вкладкам, кликает по точке и собирает ошибки консоли и сети:

```bash
cd web
node check-map.mjs        # нужен запущенный npm run dev
```

350 постов группы `ru` и 185 постов группы `foreign` на карту не попадают:
в них названа только улица или только страна. Это видно в панели справа.

## Режимы, правки и сервер

Интерфейс открывается на карте, в режиме посетителя.

**Админ** правит карточки: у каждого тега появляется крестик, а в окне
поста — кнопки «Убрать» и «Вернуть убранные теги». Убранный тег исчезает
и с карты, и из фильтров. Вход по паролю.

У админа в каждой карточке есть ещё кнопка **«Добавить в баг-репорт»** —
пометка поста, на котором разбор сработал неправильно. Вместе с пометкой
сохраняются подпись, дата и найденные места, поэтому `data/edits.json`
читается как список проблем, без открытия интерфейса.

**Посетитель** карточки не правит, но может оставить замечание — блок
«Уточнить место» в окне поста. Кроме текста можно указать точку: вставить
координаты (понимаются `55.7558, 37.6173`, десятичная запятая, запись с
`N`/`E`), нажать на мини-карту, перетащить метку или взять своё
местоположение. Вход для этого не нужен.

**Посты посетителей.** Кнопка «＋ Добавить пост» в шапке: ник, текст,
название места, точка на карте и до четырёх фотографий. Регистрации нет.
Фотографии ужимаются в браузере до 1600 px в JPEG (`web/src/images.js`),
сервер проверяет сигнатуру файла и кладёт его в `data/uploads/`, сам пост —
в `data/user-posts.json`. На карту пост попадает только после одобрения:
у админа в шапке кнопка «Модерация» со счётчиком, там же опубликованные
посты и уточнения посетителей. На карте посты посетителей — оранжевые
точки на вкладке «Россия», в фильтре по каналам — «Посты посетителей».
От ботов — скрытое поле-ловушка, пять постов в час с адреса и предел
очереди `MAX_PENDING_POSTS`.

## Интерфейс

Несколько правил, по которым сделаны кнопки и сообщения (в духе книги
Ильи Бирмана «Пользовательский интерфейс»):

- **Не спрашиваем «вы уверены?», а даём отменить.** Скрыть пост, убрать
  тег или ручную точку, удалить пост посетителя или уточнение — действие
  выполняется сразу, внизу появляется плашка «Вернуть»
  (`components/Toast.jsx`). Поэтому удаление поста посетителя мягкое:
  сервер помечает его удалённым и стирает с фотографиями через неделю.
- **Кнопки не блокируются.** Если в форме чего-то не хватает, после
  нажатия об этом говорится у самого поля; «Карта» во вкладке без
  координат объясняет плашкой, почему её нет.
- **Кнопки называются по результату:** «Закрыть», а не «Готово», если
  закрывать нечего; «Показать другие», а не «Другие».
- **Вход — ссылкой в подвале**, а не переключателем «Админ | Посетитель»:
  посетителю он не нужен.
- **Даты — для людей:** «27 июля 2025», в окне поста — с временем.
- **Похожее на кнопку нажимается:** тег места показывает все посты этого
  места. У поста без фотографий нет пустого серого блока.

## Телефоны

На ширине до 640px вёрстка перестраивается: сегменты в панели листаются
вбок, карта занимает весь экран под панелями (страница при этом не
прокручивается — иначе палец, двигающий карту, не вернул бы её к
фильтрам), а посты выбранной точки выезжают листом снизу. Окна
открываются на весь экран, фотографии в них листаются вбок. Поля ввода
на телефоне — 16px: с меньшим шрифтом iOS увеличивает страницу при фокусе.

На время теста посетителю доступна только вкладка «Россия»: по российским
местам разбор точнее всего, а зарубежные посты и посты без географии
нужны прежде всего для проверки самого разбора. Вкладки помечены
`adminOnly` в `web/src/data.js`.

Всё это хранит `server/index.js` — небольшой сервер на Express. Правки и
предложения лежат в `data/edits.json`: файл можно открыть глазами,
положить в git и скормить пайплайну. Пишется он через временный файл с
переименованием, чтобы падение на середине записи не испортило прежний.

Вход выдаёт токен, токен живёт в памяти сервера и в `localStorage`
браузера. Перезапуск сервера разлогинивает — для локального проекта это
нормально. Если сервер не поднят, интерфейс работает на чтение и говорит
об этом в панели.

Разбор правок на фронтенде — в `web/src/useEdits.js`, окно входа —
в `components/LoginDialog.jsx`.

### Настройки и защита

Настройки читаются из `server/.env`, образец — `server/.env.example`.
Node читает файл сам, через `--env-file-if-exists`, отдельной библиотеки
не нужно.

| переменная | зачем |
| ---------- | ----- |
| `ADMIN_PASSWORD` | пароль админа; локально по умолчанию `dev` |
| `TOKEN_TTL_HOURS` | сколько живёт сессия после входа, по умолчанию 12 |
| `MAX_SUGGESTIONS` | предел числа уточнений в хранилище |
| `MAX_PENDING_POSTS` | сколько постов посетителей может ждать модерации, по умолчанию 300 |
| `TRUST_PROXY` | заполнять, только если впереди nginx |
| `PORT` | порт сервера правок, по умолчанию 5174 |

Что сделано, чтобы проект можно было выложить:

- **с паролем `dev` в продакшене сервер не стартует.** При
  `NODE_ENV=production` он требует явно заданный `ADMIN_PASSWORD` и
  отказывается работать со значением по умолчанию;
- **пароль сравнивается за постоянное время** (`crypto.timingSafeEqual`):
  иначе по задержке ответа его можно подбирать посимвольно;
- **вход ограничен** десятью попытками за четверть часа с адреса, иначе
  короткий общий пароль перебирается за минуты;
- **уточнения ограничены** двадцатью в час с адреса плюс общий предел:
  ручка открыта без входа, и без этого её можно завалить мусором;
- **ключ поста проверяется по шаблону** «канал-номер», чтобы он не мог
  оказаться путём вроде `../../`, а `kind` — только `places` или `streets`;
- **сессии истекают** через `TOKEN_TTL_HOURS`.

Ограничения считаются по `req.ip` и хранятся в памяти. За обратным прокси
настоящий адрес приходит в `X-Forwarded-For`, поэтому без `TRUST_PROXY`
все посетители окажутся в одном счётчике — сервер предупреждает об этом
при запуске. Доверять заголовку без прокси нельзя: тогда ограничение
обходится его подделкой.

## Сколько весит версия только с Россией

Считает `tools/estimate_photos.py`: он берёт выборку фотографий, ужимает
её в памяти и по полученному коэффициенту оценивает весь набор.

```bash
python tools/estimate_photos.py ru
```

Для группы `ru` — 17 355 постов, у 15 420 есть фотографии:

| что | объём |
| --- | ----- |
| Сборка фронтенда (js + css) | 1.2 МБ, **340 КБ** в gzip |
| `ru.json` + `meta.json` | 14.3 МБ, **4.2 МБ** в gzip |
| Фотографии, исходники из выгрузки | 7.5 ГБ (33 957 файлов) |
| Превью 400px только для первого фото поста | **0.46 ГБ** |
| Превью 400px для всех используемых фото | **1.08 ГБ** |
| Превью 400px + версии 800px для окна поста | 5.0 ГБ |
| Превью 400px + исходники для окна поста | 8.0 ГБ |

Медианная ширина оригинала — 1090 пикселей: Telegram отдаёт уже сжатые
файлы, поэтому версия 1280px весит 91% от исходника и смысла не имеет.
Разумный компромисс для теста — превью 400px для всех фотографий плюс
800px только для первого фото каждого поста. По оценке выходило 2.7 ГБ,
на деле получилось **3.07 ГБ**: выборка из 60 фотографий занизила размер
примерно на десятую часть.

Данные фронтенд грузит одним файлом, и 4.2 МБ в gzip — это несколько
секунд на среднем канале. Если окажется медленно, `ru.json` делится по
годам или по регионам, но для теста это преждевременно.

## Выкладка на сервер

Тестовый стенд: **https://archimap.194.226.142.99.sslip.io**

Всё нужное — в папке `deploy/`: образец конфига nginx, юнит systemd и
пошаговая инструкция в `deploy/README.md`. Имя сайта получено через
sslip.io — этот DNS отдаёт адрес прямо из имени, поэтому домен не нужен,
а поддомен `archimap.<IP>.sslip.io` позволяет ужиться с другим проектом
на том же сервере.

Две ловушки, на которых спотыкается выкладка, обе дают молчаливый отказ:

- **`.mjs` отдаётся как `application/octet-stream`.** nginx не знает этого
  расширения, а браузер отказывается исполнять модуль с таким типом —
  воркер MapLibre не стартует, и карта остаётся пустой без единой ошибки
  в консоли. Лечится блоком `types` в `location /assets/`.
- **`.env` с правами 600 у root.** Служба работает от `www-data` и файла
  не видит; Node пишет «.env not found», хотя файл на месте. Нужно
  `chown root:www-data` и `chmod 640`.

Фотографии для сервера готовит `tools/build_photos.py`. Правило раскладки
одно и повторено во фронтенде (`web/src/data.js`, функция `photoURL`):
первое фото поста получает обе версии, остальные — только превью. Первое
видно в карточке и открывается крупно, остальные листают внутри окна.

```bash
python tools/build_photos.py --group ru            # 400 и 800 px, 3.07 ГБ
python tools/build_photos.py --group ru --large 0  # только превью, ~1.2 ГБ
```

Повторный запуск пропускает уже готовое, поэтому прерванную нарезку можно
продолжить.

## Источники данных

Координаты мест — GeoNames (CC BY 4.0) и OpenStreetMap (ODbL), подложка —
OpenFreeMap. Обе лицензии требуют указания источника, поэтому атрибуция
стоит в двух местах: в углу карты (через `attribution` у geojson-слоя,
рядом с подписью подложки) и в подвале страницы, который виден и в списке.

Посты и фотографии принадлежат авторам телеграм-каналов. Для закрытого
теста это нормально, для публичного сайта стоит спросить их разрешения.

## Что дальше

Группа `none` небесполезна: там много московских объектов, названных без
города («Сухарева башня», «особняк Рутковских»), — их можно доставать
отдельным справочником достопримечательностей. Следующий шаг к настоящей
карте — геокодирование пар «город + улица»: это даст точки на уровне дома
вместо центра города.
